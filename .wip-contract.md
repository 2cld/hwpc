## What Wip Monitors

| Check | How | Frequency | Alert If |
|-------|-----|:---------:|----------|
| slwin11ops reachable | ZeroTier ping / ZT API | Daily | Offline > 24h |
| Backup receiving | .backup-state shows `sl=OK` | Daily | sl=FAIL or not attempted |
| Disk space | SSH or status script (future) | Weekly | < 10% free |

## What Wip Does NOT Monitor (site responsibility)

- Power / UPS status
- ISP uptime
- Physical environment (temperature)
- LAN switch health
- *.2cld.com services (test/dev, non-critical)

## Communication

| Channel | Purpose |
|---------|---------|
| [2cld/sl issues](https://github.com/2cld/sl/issues) | Site ops issues, backup problems, service requests |
| email: ghadmin@horseoff.com | Urgent site issues |

## Wip May

- ✅ Check slwin11ops reachability (ZeroTier API, ping)
- ✅ Read backup state (sl=OK/FAIL in .backup-state)
- ✅ Create issues on 2cld/sl for findings
- ✅ Run read-only status commands via SSH (future: sl-status.sh)

## Wip May NOT

- ❌ Modify files on slwin11ops
- ❌ Restart services
- ❌ Delete backup data
- ❌ Manage Hyper-V VMs
- ❌ Change network config

## Escalation

| Situation | Wip Action |
|-----------|-----------|
| slwin11ops offline > 24h | Issue on 2cld/sl + email ghadmin |
| Backup not received (sl=FAIL) | Issue on 2cld/sl (likely cf-side problem — check backup-daily.sh) |
| Disk space critical | Issue on 2cld/sl |
| Site unreachable (all equipment) | Escalate to site admin (power/ISP issue) |
